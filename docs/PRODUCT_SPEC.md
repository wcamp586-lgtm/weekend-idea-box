# 周末灵感盒：MVP 产品规格

## 1. 一句话产品定义

周末灵感盒是一个单人使用的小工具：随手收集想看的电影、想玩的游戏、想去的地方和想做的活动，在周末通过筛选或随机抽取快速作决定。

## 2. 目标用户与真实问题

目标用户是“平时看到不少好点子，但真到周末又想不起来”的个人用户。

产品解决的不是“没有推荐”，而是两个更窄的问题：

1. 灵感散落，难以集中保存。
2. 选项很多，临时决定时容易纠结。

## 3. 核心路径

添加一个灵感 → 在列表中看到它 → 按分类或状态找到它 → 随机抽中一个可执行选项。

只要这条路径完整可用，MVP 就成立。

## 4. MVP 功能范围

### 必须有

- 新增、编辑和删除灵感。
- 分类：电影、游戏、地方、活动。
- 状态：想做、进行中、已完成。
- 按关键词、分类和状态筛选。
- 从当前可见的“想做”项目中随机抽取一个。
- 使用浏览器 `localStorage` 保存数据。
- JSON 数据导入和导出。
- 桌面与手机布局可用。
- 核心流程有自动化测试。

### 明确不做

- 账号、登录、多人协作或云同步。
- AI 自动推荐、地图导航或第三方内容抓取。
- 支付、会员、社交分享或消息通知。
- 原生手机 App、服务器和数据库。

这些功能不是永远不做，而是不进入本轮 20 小时训练。

## 5. 数据模型

每条灵感只保留完成核心路径所需的数据：

```ts
type Inspiration = {
  id: string
  title: string
  category: 'movie' | 'game' | 'place' | 'activity'
  status: 'todo' | 'doing' | 'done'
  note: string
  createdAt: string
  updatedAt: string
}
```

浏览器存储使用带版本号的最小外壳，避免以后字段变化时无法迁移：

```ts
type StoredData = {
  version: 1
  inspirations: Inspiration[]
}
```

读取到未知版本或损坏数据时，应用必须进入可恢复的错误状态，不能静默覆盖原数据。

## 6. MVP 验收标准

1. 用户可以填写标题、分类、状态和备注并成功新增一条灵感。
2. 新增内容立即出现在列表中，刷新浏览器后仍然存在。
3. 用户可以编辑和删除已有灵感，删除前必须确认。
4. 搜索、分类和状态可以组合筛选，结果数量正确。
5. “随机抽一个”只从当前符合条件且状态为“想做”的项目中抽取。
6. 没有数据或没有筛选结果时显示清晰的空状态。
7. 手机宽度下没有横向溢出，主要按钮可触摸操作。
8. 自动化测试覆盖新增、筛选、删除和刷新保留四条主流程。
9. `pnpm lint` 和 `pnpm build` 通过。

## 7. 成功边界

本项目追求的是“小而完整、可验证、可发布”，不是功能数量。任何新增想法，必须先回答：它是否直接帮助核心路径？如果不是，放入以后再做清单。
